# 카페24 상품상세 "골라담기" 커스텀 옵션 UI

카페24 상품 상세페이지에서 **기본 구매 흐름(옵션 선택 · 선택상품 목록 · 장바구니 · 바로구매)을 그대로 유지**하면서, 그 위에 "골라담기" 형태의 커스텀 옵션 UI를 얹은 구현입니다. 구매/금액/장바구니 로직은 재구현하지 않고 카페24 기본 로직을 그대로 사용합니다.

## 핵심 설계 원칙 (과제 의도 우선)

과제는 "**디자인 100% 재현보다 카페24 옵션 연동의 안정성을 우선**"한다고 명시합니다. 이 원칙에 따라 다음을 **의식적으로** 결정했습니다.

- **시안의 "맛 선택" 시트는 의도적으로 구현하지 않았습니다.** 피그마 시안(한끼통살)은 "개입 선택 → 맛을 수량 스테퍼로 채우기"의 2단계지만, **표준 테스트 상품에는 '맛' 옵션이 존재하지 않습니다.** 과제가 지정한 옵션값은 `10/30/50/100개입_1,_2`뿐이며, suffix `_1,_2`는 "맛"이 아니라 **"같은 개입수의 추가 가능 횟수"**입니다. 즉 과제는 시안의 골라담기 개념을 **"사이즈 선택 + 반복 추가 횟수"**로 재정의했습니다.
  - 존재하지 않는 맛 데이터로 UI를 만들면, 화려해 보여도 **선택 결과가 실제 카페24 주문/품목에 반영되지 않는 '장식용 UI'**가 됩니다. 이는 "실제 옵션 연동"이라는 과제 핵심과 정반대입니다. 그래서 맛 시트 대신 **8개 옵션의 연동·동기화·중복방지·횟수제한을 견고하게** 만드는 데 집중했습니다.
  - (개입 선택 카드 자체의 시각 디자인·색·간격·뱃지는 시안 규격에 맞췄습니다.)
- **카페24 기본 구매 로직은 재구현하지 않습니다.** 커스텀 UI는 기본 옵션을 대신 눌러주는 보조 레이어이며, 가격·수량·장바구니·바로구매는 전부 카페24 기본 로직이 처리합니다.

## 구현 하이라이트

- **양방향 동기화(단일 진실 원천):** 별도 카운터에 의존하지 않고 카페24 선택상품 목록(`#totalProducts`)의 실제 DOM을 `MutationObserver`로 감시해 카드 상태를 재계산합니다. 카드로 담든, 목록에서 직접 삭제하든 항상 일치합니다.
- **연타 중복 방지(낙관적 잠금):** 클릭 직후 `state.pending`에 등록해 카페24 반영 전 같은 옵션이 두 번 담기는 것을 막고, 반영이 확인되거나 타임아웃(800ms) 시 해제합니다.
- **비반응형 스킨 모바일 대응:** 베이직 스킨은 뷰포트 메타가 없어 CSS `@media`가 모바일에서 켜지지 않습니다. JS가 UA/`screen.width`/`innerWidth`로 모바일을 감지해 `body.pick-mobile`을 부여하고 하단 바텀시트(고정 트리거 바 + 시트)를 노출합니다.
- **스킨 무관 셀렉터:** 옵션 탐색을 특정 컨테이너(`.infoArea` 등)에 의존하지 않고 세트/추가구성 옵션만 제외하는 방식으로 작성해, PC/모바일 스킨에서 동일 파일이 동작합니다.
- **접근성:** `aria-pressed`, `aria-live` 상태 표기, `:focus-visible` 포커스 링, ESC로 시트 닫기 지원.

## ① 옵션 UI 구현 방식

- 카페24 기본 **텍스트버튼 옵션**(옵션값 8개: `10/30/50/100개입_1,_2`)은 **DOM에 그대로 유지**합니다. (삭제 금지 — 구매 로직이 이 요소를 사용)
- 초기화 시 JS가 기본 옵션 버튼을 스캔(`findNativeOptionButtons`)해 `_숫자` suffix를 떼고 `10/30/50/100개입` **그룹으로 묶은 뒤**(`groupNativeOptions`), `#pickOptionsList`에 그룹별 카드(행)를 렌더링합니다.
- 카드 클릭 → 해당 그룹의 "아직 안 담긴 다음 옵션값"의 **네이티브 옵션 요소를 프로그래밍 방식으로 `click`** → 카페24 선택상품 목록(`#totalProducts`)에 품목이 추가됩니다.
- **가격·수량·장바구니·바로구매는 전부 카페24 기본 로직**이 처리합니다. 커스텀 UI는 기본 옵션을 대신 눌러주는 보조 레이어일 뿐입니다.

## ② 외부 설정 JS 구조 (`pick-options.config.js`)

표시용 데이터(구매 로직과 무관)를 **설정 파일 한 곳에만** 모아, 개발 지식 없이 값만 바꿔도 카드 표시가 바뀌도록 분리했습니다.

```js
window.PICK_OPTION_CONFIG = {
  optionSuffixPattern: /_(\d+)$/,   // 옵션값 끝 _1,_2 를 추가 가능 횟수로 해석
  groups: {
    '30개입': {
      price: '70,500원',        // 표시용 가격(문자열)
      discount: '29% 할인',     // 할인율 문구
      perUnit: '1개 : 2,350원', // 개당 가격
      badge: '가장 많이 사요',   // 뱃지 문구(없으면 미표시)
      badgeType: 'accent',      // 'accent'(주황) | 'max'(빨강)
      order: 2,                 // 카드 노출 순서
    },
    // 10/50/100개입 …
  },
};
```

- `price`/`discount`/`perUnit`은 **화면 표시용 문자열**이며, 실제 결제 금액은 카페24 옵션/장바구니 로직을 그대로 따릅니다.
- 뱃지·추천문구·노출순서 등 "바뀔 수 있는 데이터"는 전부 여기에만 존재하고, `pick-options.js`에는 동작 로직만 둡니다. (표시값 ↔ 동작 로직 역할 분리)

## ③ 카페24 옵션과 동기화한 방식

- **양방향 동기화:** 카페24 선택상품 목록(`#totalProducts`)을 `MutationObserver`로 감시합니다. 카드 클릭으로 담기든, 목록에서 직접 삭제(×)하든 → 카드의 카운트/활성화 상태가 자동으로 갱신됩니다.
- **중복 방지(연타 대응):** 클릭 직후 해당 옵션을 `state.pending`(낙관적 잠금)에 등록해, 카페24 반영 전에 같은 옵션이 두 번 담기는 것을 막습니다. 반영이 확인되거나 800ms(`PENDING_TIMEOUT`)가 지나면 잠금을 해제합니다.
- **횟수 제한:** 옵션값 suffix(`_1`,`_2`) 개수 = 그룹별 최대 추가 횟수입니다. (예: `30개입_1`,`30개입_2` → 최대 2회) 초과 클릭 시 담기지 않고 안내 메시지를 노출하며, 다 담은 카드는 `is-complete`로 표시됩니다.
- **활성화 표시:** 담긴 카드는 `is-selected`(액센트 테두리/배경 + 체크), 카운트 `N / max` 뱃지, `aria-pressed="true"`로 상태를 명확히 표시합니다.

### 모바일 처리 (바텀시트) 와 스킨 제약 — 중요

- 카페24 **베이직 PC 스킨은 뷰포트 메타태그가 없는 비반응형 스킨**이라, CSS `@media` 쿼리가 모바일에서 기대대로 켜지지 않습니다.
- 그래서 `pick-options.js`가 **UA / `screen.width` / `innerWidth`로 모바일을 감지(`isMobileContext`)해 `body.pick-mobile` 클래스를 부여**하고, CSS는 그 클래스를 기준으로 하단 바텀시트(하단 고정 트리거 바 + 백드롭 + 시트 + 완료 버튼)를 켭니다. (뷰포트 메타 유무와 무관하게 동작)
- PC(데스크톱)는 옵션 영역에 인라인 카드로, 모바일은 하단 고정 바를 탭하면 올라오는 바텀시트(모달)로 노출됩니다. 시트는 `position:fixed`라 **터치 영역과 구매 버튼 영역이 겹치지 않습니다.**
- ⚠️ **모바일 확인 시 페이지 전체가 축소돼 보이는 것은 베이직 스킨이 비반응형이기 때문이며, 이는 "옵션 영역 외 디자인 변경 금지"라는 과제 범위 밖입니다.** 우리 옵션 위젯 자체는 이 제약 안에서 PC 카드 ↔ 모바일 바텀시트로 정상 전환됩니다.

## 범위 관련 참고 / 제한 사항

- **시안의 "맛 선택" 시트 미구현:** 사유는 위 [핵심 설계 원칙](#핵심-설계-원칙-과제-의도-우선) 참고 (표준 테스트 상품에 맛 옵션이 없어 과제 범위 밖 · 장식용 UI 지양).
